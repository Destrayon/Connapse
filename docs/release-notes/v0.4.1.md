# Connapse v0.4.1

**The one-command install survives a reboot, and agents wait for your approval and carry on by themselves.**

## What's new

- **Approvals agents can wait on.** When Connapse holds an agent's delete for approval, the agent calls the new `approval_status` tool, waits for your decision, and repeats the call once you approve it. You can leave it a reason. Only the person the request belongs to can approve or deny it.
- **Agents make their own memory spaces** with `memory_space_create`. No `my-memory` space is made for you any more, and memory spaces no longer show up as file containers.
- **Fewer calls for files.** List a folder's newest files with their dates, read up to 50 files in one call, and append to a text file. A text file can be read as soon as it is uploaded, before indexing finishes.
- **A web route for every agent tool.** Fact memory, the memory timeline and the code tools now have REST routes that give the same answers as their MCP tools.

## Fixes

- The one-command install restarts after a reboot, with MinIO and Ollama pinned to fixed images.
- Searches recover by themselves when the database is slow to start, instead of staying refused until a restart.
- `connapse auth login` and apps with a `localhost` callback sign in to a server reached over plain http.
- A fact saved with a date-only start can be corrected the same day.

## Upgrade

```bash
# in .env
CONNAPSE_VERSION=v0.4.1
```

```bash
docker compose pull web
docker compose up -d
```

Use the `docker-compose.yml` from this release's package to get the restart policy and pinned images. If an agent or script saves facts to `my-memory` without creating it, create that space once; an existing one is kept.
