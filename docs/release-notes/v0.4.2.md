# Connapse v0.4.2

**Approve an agent's delete and Connapse carries it out. The agent no longer has to repeat it.**

If your agent waits with `approval_status` and then repeats a held delete, change it to read the batch with `deletion_status` instead and not repeat the call.

## What's changed

- **Every held delete is a batch Connapse carries out.** When an agent's token asks before deleting, a single delete now works like `request_deletions`: deleting a file, a folder, an empty container, a memory space or a memory fact, or up to 50 files at once, puts a batch on the Approvals page. Once you approve it, Connapse deletes the approved items itself, skipping anything that changed since the agent asked, and the agent reads each outcome with `deletion_status`. One exception: a file replaced at the same path by one of the same size and type isn't seen as changed, so the replacement is deleted. In v0.4.1 the agent had to wait for your approval and then repeat the call.
- `request_deletions` also takes empty containers and memory facts.
- Held calls that aren't deletions of your knowledge, such as setting a credential or removing a user, still work as before: the agent waits with `approval_status` and repeats the call once you approve it.
- **One tool each for reading, uploading and deleting files, one file or many.** `get_document` now reads up to 50 documents at once, `upload_file` uploads up to 100 files, and `delete_file` deletes up to 100, or up to 50 when the delete is held for approval, since a batch holds at most 50 items. They replace `get_documents`, `bulk_upload` and `bulk_delete`, which still work and give the same results but no longer appear in the tool list an agent loads. Those three old names will be removed after the 0.4.x releases, so switch any scripts or agent prompts that use them.

## Upgrade

If you started Connapse with the README's one-command start (`docker compose -f oci://ghcr.io/destrayon/connapse:compose up -d -y`), follow [Upgrade Connapse](https://github.com/Destrayon/Connapse/blob/v0.4.2/docs/self-host/upgrade.md) instead of the steps below. If you run a downloaded `docker-compose.yml`:

```bash
# in .env
CONNAPSE_VERSION=v0.4.2
```

```bash
docker compose pull web
docker compose up -d
```

From v0.4.1 there is no migration and no change to `docker-compose.yml`. From an older version, follow [Upgrade Connapse](https://github.com/Destrayon/Connapse/blob/v0.4.2/docs/self-host/upgrade.md), which covers each release in between.

Every change is in the [changelog](https://github.com/Destrayon/Connapse/blob/v0.4.2/CHANGELOG.md).
