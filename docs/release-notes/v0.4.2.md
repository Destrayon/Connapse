# Connapse v0.4.2

**Approve an agent's delete and Connapse carries it out. The agent no longer has to repeat it.**

## What's changed

- **Every held delete is a batch Connapse carries out.** When an agent's token asks before deleting, a single delete now works like `request_deletions`: deleting a file, a folder, an empty container or a memory fact, or several files at once, puts a batch on the Approvals page. Once you approve it, Connapse deletes the approved items itself, skipping anything that changed since the agent asked, and the agent reads each outcome with `deletion_status`. In v0.4.1 the agent had to wait for your approval and then repeat the call.
- `request_deletions` also takes empty containers and memory facts.
- Held calls that aren't deletions of your knowledge, such as setting a credential or removing a user, still work as before: the agent waits with `approval_status` and repeats the call once you approve it.
- **One tool each for reading, uploading and deleting files, one file or many.** `get_document` now reads up to 50 documents at once, `upload_file` uploads up to 100 files, and `delete_file` deletes up to 100. They replace `get_documents`, `bulk_upload` and `bulk_delete`, which still work and give the same results but no longer appear in the tool list an agent loads. Those three old names will be removed after the 0.4.x releases, so switch any scripts or agent prompts that use them.

## Upgrade

```bash
# in .env
CONNAPSE_VERSION=v0.4.2
```

```bash
docker compose pull web
docker compose up -d
```

There is no migration and no change to `docker-compose.yml`.
