# Connapse v0.4.3

**MCP clients stay signed in, and big uploads stop holding up small ones.**

## Fixed

- **MCP clients stay signed in across weeks of normal use.** Clients such as Claude Code were asked to sign in again far too often. A client's sign-in now lasts 30 days unused instead of 7, and each renewal starts the 30 days again. Two sessions that share one sign-in and renew it at the same moment both stay signed in, because a token that was just renewed still works for 30 seconds; before, the second renewal looked like a stolen token and both sessions were signed out. Renewals also no longer run into a limit shared with password sign-in. Signing out of the browser doesn't sign MCP clients out, and revoking a client or removing a user still stops it renewing its sign-in right away. As before, an access token it already holds keeps working until it expires, at most an hour later.
- **Large files no longer hold up everyone else's uploads.** Files of 2 MiB or more are processed on two workers of their own, so a batch of big PDFs can't keep small uploads waiting for hours. Two new settings change the split: `Hangfire__LargeIngestionWorkerCount` (how many large files are processed at once, default `2`) and `Hangfire__LargeDocumentBytes` (the size from which a file counts as large, default `2097152`, 2 MiB). See [Configuration](https://github.com/Destrayon/Connapse/blob/v0.4.3/docs/reference/configuration.md#server).
- **`connapse auth login` says why it couldn't find its client.** When the sign-in page couldn't fetch the CLI's client file, often because a reverse proxy refused the Connapse server's own request, it said only "Unknown or unregistered client." It now also shows the file's URL and the HTTP status that came back (#1202, reported by @marcusyoung).
- **Release images say their own version and commit.** `docker inspect` showed the version `24.04`, which came from the Ubuntu base image. Images now carry Connapse's version, the commit they were built from and the repository's address (#1202, reported by @marcusyoung).

## Tests

- A new test checks that MCP uploads put each file in the folder path they're given, so files with the same name in different folders don't collide. They already did; the test keeps it that way.

## New settings

| Setting | Default | What it does |
|---|---|---|
| `Hangfire__LargeIngestionWorkerCount` | `2` | Large files processed at once, on workers of their own |
| `Hangfire__LargeDocumentBytes` | `2097152` | Size in bytes from which a file counts as large |
| `Identity__Jwt__RefreshTokenReuseIntervalSeconds` | `30` | How long a just-renewed sign-in token still works; at most 60, `0` turns it off |
| `RateLimiting__TokenPermitLimit` | `120` | Sign-in token requests allowed per IP address in each window |
| `RateLimiting__TokenWindowSeconds` | `60` | Length of that window in seconds |

`Identity__Jwt__RefreshTokenLifetimeDays` now defaults to `30` instead of `7`. If you set it to `7` yourself, remove it to take the new default.

## Upgrade

If you started Connapse with the README's one-command start (`docker compose -f oci://ghcr.io/destrayon/connapse:compose up -d -y`), follow [Upgrade Connapse](https://github.com/Destrayon/Connapse/blob/v0.4.3/docs/self-host/upgrade.md) instead of the steps below. If you run a downloaded `docker-compose.yml`, first make a backup with [Back up and restore Connapse](https://github.com/Destrayon/Connapse/blob/v0.4.3/docs/self-host/backup-and-restore.md), since this release runs a migration and rolling back means restoring it. Then:

```bash
# in .env
CONNAPSE_VERSION=v0.4.3
```

```bash
docker compose pull web
docker compose up -d
```

From v0.4.2 there is no change to `docker-compose.yml`. One migration adds a column to the sign-in tokens table; it runs when the app starts, and clients signed in before the upgrade stay signed in. From an older version, follow [Upgrade Connapse](https://github.com/Destrayon/Connapse/blob/v0.4.3/docs/self-host/upgrade.md), which covers each release in between.

Every change is in the [changelog](https://github.com/Destrayon/Connapse/blob/v0.4.3/CHANGELOG.md).
