# How should Connapse adapt hybrid-search fusion to each deployment: agent ratings, synthetic queries, or a tuned default?
**Date:** 2026-09-28
**Status:** Reviewed
**Built on:** hybrid-fusion-improvements-2026-09-27.md (per-query α predictors, fusion functions, dev-suite design)

## Executive summary
Five options were compared for adapting Connapse's hybrid fusion weight α (the convex-combination weight between min-max-normalised dense and BM25 scores) to each deployment: a well-tuned global default, live ratings from calling AI agents via an MCP tool, LLM-generated query sets per container, admin-labelled query sets, and corpus statistics. No product or paper tunes fusion weights automatically from ratings; the closest precedent, OpenSearch's Search Relevance Workbench, grid-searches fusion settings offline on judgments and leaves deployment to a human. The evidence favours a global default tuned offline on the multi-domain dev suite (α transfers across domains and converges on few queries), with any per-container adaptation as an opt-in override gated on a statistically clear win. Agent ratings are the weakest per-container signal: LLM judges only separate clearly different configurations, small models are near chance per passage, and judges are easy to manipulate with injected text. If ratings are collected, the right unit is the union of top-10 lists across an α grid, replayed offline — which Connapse's new candidate capture and replay tool already supports.

## Research brief
**Question:** Which approach should Connapse use to adapt fusion (α and related settings) to a deployment's data, and how would the agent-rating idea fit if adopted?
**Sub-questions:** (1) learning fusion settings from feedback over time; (2) reliability of LLM/agent relevance ratings; (3) what products do; (4) security and privacy of feedback-driven tuning; (5) alternatives: synthetic queries, corpus signals, admin judgments, robust defaults.
**Out of scope:** per-query α predictors at serve time (covered in hybrid-fusion-improvements-2026-09-27.md: oracle headroom ~20%, cheap predictors capture 0–3%).
**Success criteria:** a ranked recommendation with the evidence and guardrails for each option.

## Option 1 — a global default tuned offline (recommended baseline)
A single α tuned on many domains is the strongest evidence-backed option for Connapse. Bruch et al. (TOIS 2023, arXiv 2210.11934) found α converges with under 5% of training data and a single α tuned on MS MARCO, NQ and Quora beat RRF out of domain. Connapse's 8-domain BEIR dev suite gives ~767 fully judged queries — more than production ratings would supply for a long time. Because Connapse's cross-encoder reranker only reorders what fusion hands it, α should also be tuned for recall at the reranker's candidate depth when the reranker is on; the claim that reranking flattens α sensitivity is mechanistically sound but unquantified in the literature, so Connapse should measure it on the dev suite. Confidence: high that a tuned global default is a strong baseline; low on how much the reranker flattens the α curve.

## Option 2 — learning from agent ratings over time
Learning α from agent ratings is feasible but only pays off for large, unusual containers, and needs strong guardrails.
- **No online-learning machinery needed.** Dueling bandits, interleaving and counterfactual (IPS) evaluation exist because feedback usually covers only what was served (Yue & Joachims ICML 2009; Schuth et al. CIKM 2014; Joachims et al. WSDM 2017). If every candidate in the union of top-10 lists across an α grid is rated, nDCG@10 is exact for every grid point, and tuning is an offline grid replay. Rating only the served top-k biases comparisons toward the current α (TREC pooling logic). Confidence: high.
- **Sample size is the binding constraint.** For a paired test at 5% significance and 80% power, n ≈ 7.85·σ²/δ² (Webber, Moffat & Zobel CIKM 2008; Sakai IRJ 2016). Detecting δ = 0.02 nDCG@10 needs ~50 queries if the per-query σ of differences between neighbouring α values is 0.05, ~200 at σ = 0.10, ~440 at σ = 0.15. Connapse can measure σ from its dev-suite replay; most containers will not reach a few hundred rated queries.
- **Judge quality.** Strong LLM judges agree only moderately with humans per passage (κ 0.2–0.64, Thomas et al. SIGIR 2024; UMBRELA κ 0.31–0.50) but rank clearly different systems like humans (τ ≈ 0.9, TREC RAG 2024). Among close competitors agreement collapses (τ 0.51 among top 20; a judge-gaming system ranked 5th by the judge and 28th by humans — Clarke & Dietz, arXiv 2412.17156). Choosing between neighbouring α values is that weak case. 7–8B judges vary from κ 0.25 (Llama-3-8B) to near chance (Mistral-7B) (JudgeBlender, arXiv 2412.13268). A caller's model is unknown, so ratings need a small human-labelled anchor to be calibrated.
- **Bias direction is unresolved.** Judges over-reward query-term matches (Alaofi et al. SIGIR-AP 2024 — pulls toward BM25) and favour LLM-based rankers (Balog et al. SIGIR 2025). Batched ratings suffer threshold priming and position effects (arXiv 2409.16022); pointwise, reasoning-first, binary or 0–3 labels are more reliable.
- **Precedent.** No product tunes fusion weights from ratings. Onyx, Algolia and Coveo apply feedback as bounded or thresholded per-document boosts; OpenSearch only evaluates. Sanity's MCP `give_feedback` tool routes free-text reports to humans and limits when agents are prompted to use it, to avoid floods.

## Option 3 — per-container synthetic query sets
Generating queries from a container's own documents, pooling results across fusion settings and judging them with a fixed, known LLM is the most practical per-container signal, but it has not been validated for tuning α. Rahmani et al. (SIGIR 2024, arXiv 2405.07767) found synthetic queries with pooled judgments rank systems close to real queries (τ 0.82–0.86), while treating only the source passage as relevant fails (τ 0.157). LARMOR (Khramtsova et al., SIGIR 2024) reached τ 0.55–0.63 with per-dataset τ 0.38–0.77, unreliable on some corpora. The concern that generated queries echo their source passage's wording and so favour BM25 is plausible and unmeasured for α. It removes the unknown-caller problem (Connapse chooses the judge) but keeps judge leniency and term-matching bias. It can be validated on the 8 dev datasets by comparing the α it picks with α tuned on real labels.

## Option 4 — admin judgment lists
An admin-labelled set of 30–50 queries per container is the most trustworthy per-container signal but costs admin effort, so it suits high-value deployments only. IR convention is at least 25–50 topics for reliable comparison (Buckley & Voorhees SIGIR 2000); ARES (NAACL 2024) needed ~100–150 human labels and combines them with LLM judges via prediction-powered inference. Such a set also serves as the holdout that gates any automatic change.

## Option 5 — corpus statistics without queries
No evidence shows corpus statistics predict the best α per collection. Score-based query-performance predictors had negative average τ for choosing retrievers (LARMOR Table 2; Khramtsova et al. SIGIR-AP 2023). Corpus features (code vs prose, vocabulary rarity) are at most a prior for a starting value.

## Security and privacy of feedback-driven tuning
Feedback tuning adds an attack channel on top of corpus poisoning, and LLM judges are easy to steer. PoisonedRAG (USENIX Security 2025) reaches ~90% attack success with 5 injected texts; online learning-to-rank can be driven by fake feedback at sublinear cost (arXiv 2305.17071, 2305.19218). Indirect prompt injection (Greshake et al. AISec 2023) lets a document instruct the rating agent; judges label passages relevant when the query or a line like "this passage contains the answer" is pasted in (arXiv 2501.17969), and single tokens trigger false positives across models (arXiv 2507.08794). Learning only 1–3 global parameters limits the damage, but a global α lets one tenant's ratings change another's ranking. Stored queries and ratings are sensitive (the AOL log release re-identified users). Guardrails: per-container scope only; accept ratings only for results the rater's permission check returned; aggregate per rater with a trimmed mean or median and count at most one rating per (rater, query, document); clamp α to an admin range and cap per-update movement; require a minimum number of distinct raters; check every change against a frozen holdout and keep one-click rollback; store raw queries only in the container's scope with a retention limit. The synthetic-query option shares the poisoning risk: a document can steer which queries are generated, so sources should be restricted and each document's contribution capped.

## Recommendation for Connapse
1. **Now (#552):** tune the global default on the dev suite with the candidate replay, for nDCG@10 without the reranker and recall at the reranker depth with it. Measure σ of per-query differences between neighbouring α values; it decides whether any per-container tuning is achievable.
2. **Next, opt-in:** a per-container calibration command that generates queries from the container's documents, pools results across the α grid, judges them with an admin-chosen LLM, replays offline, and proposes a setting only if it beats the global default by a bootstrap margin — an admin approves it (OpenSearch's shape). Validate on the 8 dev datasets first.
3. **Agent ratings, if built:** an MCP tool whose ratings land in a per-container judgment store and feed the same offline replay as a drift monitor and extra judgments, never applied directly; ask agents to rate the pooled grid union pointwise, not only what they were served; all guardrails above.
4. **Admin judgment lists** as the holdout and for high-value containers.

## Conflicts and uncertainties
- LLM judges' net bias between BM25 and dense retrieval: evidence points both ways (term-match leniency vs preference for LLM-like rankers).
- Whether a reranker makes α matter less: mechanistically expected, unquantified.
- Synthetic queries: good for system rankings, untested for choosing α; possible BM25 bias.
- σ for neighbouring α values (0.05 vs 0.15) changes the per-container sample requirement fourfold; not yet measured.

## Gaps — what we did not find
- Any system or paper that tunes hybrid fusion weights from user or LLM feedback over time.
- A comparison of α tuned on synthetic queries against α tuned on real queries for the same corpus.
- A study validating an agent's citations or usage as relevance labels.
- Peer-reviewed guidance on bounded ranges or admin approval for automatic ranking changes (practice only).

## Source quality assessment
Mostly primary: peer-reviewed IR papers (SIGIR, TOIS, ICTIR, WSDM, NAACL, USENIX Security), arXiv papers from the authoring groups, and vendor documentation or source code (OpenSearch, Onyx, Algolia, Coveo, Vespa, Qdrant, Sanity). Glean's 20% figure is marketing. Security claims about bounded global parameters are the researchers' reasoning, flagged thin.
