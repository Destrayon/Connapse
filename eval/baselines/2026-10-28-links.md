# Link search off and on, 2026-10-28 (CON-107)

The finished link features (CON-33, 34, 36, 37, 39) measured against the pass bars in `eval/pass-bars.md`.
`hybrid` is the app's defaults; `hybrid-links` adds `Knowledge:Search:EnableLinkSearch=true`. Both configs search
the same index, built once per dataset, so links are written in both and only the search differs.

**Code.** `epic/con-e3-links-and-memory` at `4446ef4`.

**Runs.** 2026-10-28 on DESKTOP-R1I9RUA, nomic-embed-text through Ollama on the GPU (one request in flight),
reranker off. Containers capped at 2 CPUs (Ollama 4 GB, Postgres and MinIO 2 GB), 2 ingestion workers,
below-normal priority. Index times are on the GPU, so they don't compare with the CPU baseline of 2026-10-24.

## Link suites

Every dataset improves, and every nDCG@10 and MRR@10 gain is significant (Holm-corrected permutation p < 0.05).

| Dataset | Test queries | Links written | nDCG@10 off → on | MRR@10 off → on | Recall@10 off → on | p95 ms off → on | Indexed in |
|---|---|---|---|---|---|---|---|
| links-connapse-github | 48 | 217 | 0.547 → **0.611** | 0.465 → **0.510** | 0.767 → **0.868** | 47 → 78 (+31) | 53 s |
| links-flink-jira | 85 | 7,474 | 0.238 → **0.410** | 0.202 → **0.318** | 0.372 → **0.664** | 194 → 304 (+110) | 304 s |
| links-connapse-github-2 | 37 | 385 | 0.569 → **0.619** | 0.521 → **0.573** | 0.751 → 0.786 | 51 → 59 (+9) | 44 s |
| links-flink-atlassian | 160 | 8,757 | 0.220 → **0.323** | 0.185 → **0.257** | 0.375 → **0.541** | 403 → 473 (+70) | 318 s |

Bold is a significant gain. "Links written" counts every link in the records' metadata, not only the ones the
questions are graded on.

**Linked-sources bar.**

- **links-v1 MRR@10:** passes, at +0.081 against a bar of +0.05.
- **Recall@10 on the list kinds:** 4 of 6 kinds pass; the other 2 are not shown. gh-siblings +0.153,
  jira-duplicate +0.273, jira-subtasks +0.348 and jira-siblings +0.125 clear +0.10. gh-subissues (1 question) and
  gh-epic-delivery (3 questions) are at 1.000 both off and on, so they leave no room to show a gain.
- **Drops:** no question kind drops. The largest fall is jira-siblings MRR@10 on links-v3, down 0.017.
- **p95:** passes. Every dataset's p95 grows by +9 to +110 ms, inside the +150 ms allowed.
- **AI tokens:** 0, because link search makes no LLM call.

**Not established by this run.**

- **No regression on the other suites.** v1 and pdfqa-v1 were not run (enterprise-v1 was; see below). Both
  write 0 links; `Search_LinkLayerOnWithoutLinks_IdenticalToOff` covers that case in tests, but it is not measured here.
- **Branch-point comparison.** Off and on share one index at `4446ef4`. Links-off scores match the 2026-10-24
  pre-change links-v1 baseline exactly (nDCG@10 0.547 and 0.238, MRR@10 0.465 and 0.202, Recall@10 0.767 and 0.372),
  so ranking with links off is unchanged since the branch point.
- **Index cost (+10%).** Not measured. Off and on share one index, and these runs used the GPU while the 2026-10-24
  baseline used the CPU (25 s and 181 s there, 53 s and 304 s here), so the times can't be compared.

## enterprise-v1

EnterpriseRAG-Bench (`erb-50k`, 50,000 documents) carries no connector metadata, so the harness writes **0 links**
on it. This run can only show that turning link search on does no harm, not that it helps. The bar is identical
rankings with p95 at most +10% (the engine-layer row, since no links exist); the linked-sources +150 ms is reported
alongside. Measuring help at company scale needs a set with real link metadata (proposed ticket in the PR).

**Passes.** The full 50,000 documents, 470 test queries, run 2026-10-29 at `cae17d6` (docs-only on top of
`4446ef4`) with Postgres and MinIO at 4 GB, 1 ingestion worker, and the eval paused whenever free memory fell
under 14 GB.

| | Off | On |
|---|---|---|
| nDCG@10 | 0.620 | 0.620 |
| MRR@10 | 0.619 | 0.619 |
| Recall@10 | 0.733 | 0.733 |
| p50 ms | 1,392 | 1,383 |
| p95 ms | 1,721 | 1,725 (+4, +0.2%) |
| Errors | 0 | 0 |

The rankings are identical, not just the scores: the two TREC run files match line for line on query, document
and rank (4,700 lines each). `compare` reports no change on any metric (Holm p = 1.0). Indexing took about 15.5 h
of wall time, including the pauses and the GPU's single request, so it says nothing about index cost.
